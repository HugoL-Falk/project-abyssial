# Knowledge Base Redesign — Token-Efficient Memory for Claude

**Date:** 2026-06-18
**Intent:** Eliminate stale info and competing "truths" across `knowledge/`, optimised for Claude's token cost (not human readability).

---

## Problem

Three coupled symptoms in the current `knowledge/` system, all roughly equal weight:

1. **Stale hand-summaries lie.** `knowledge/cards/*.md` (14 files) duplicate content from `src/data/cards/*.ts` and drift silently. The summaries are read with full trust; the drift is not visible.
2. **`decisions.md` contradicts itself.** 282 lines of append-only ledger with no superseded-by mechanism; reversals sit next to the original decisions and both look authoritative.
3. **Token bloat at startup.** README mandates reading the latest `session-NN.md`; 35 active session files have accumulated (sessions 52–86), and each session log runs long.

User explicit constraint: **optimise for Claude's grep/read efficiency, not human ergonomics.** Dense formats, structured one-liners, and grep-on-demand are preferred over prose.

---

## Design

Five coordinated changes. All scoped to the `knowledge/` folder + a new `scripts/` entry + a pre-commit hook + a `CLAUDE.md` rewrite of the startup/shutdown routine.

### 1. Cards — auto-derived index

- **Delete** all 14 `knowledge/cards/*.md` hand-summary files. Git history preserves them.
- **New file** `knowledge/cards/INDEX.md`, regenerated by `scripts/gen-knowledge-cards.ts` from `src/data/cards/*.ts`.
- **Format:** one line per card, pipe-delimited, no prose.
  ```
  | id | title | tier | tags | prep_carrier | defer_carrier | option_count | flavour_hash |
  | the_old_book | The Old Book | core | study,prep | studied | - | 3 |  a4f2 |
  ```
- `prep_carrier` = which prep tag this card's options can set (`studied`/`attended_seance`/`opium_pact`/`recited`/`-`).
- `defer_carrier` = `yes` if any option carries `deferGodPathCard`, else `-`.
- `flavour_hash` = short hash of concatenated flavour text; changes when card content changes, useful for "did this card move since last week" greps.
- Target size: < 200 lines, < 4000 tokens for full index.
- For per-card detail, Claude reads `src/data/cards/<file>.ts` directly. No markdown intermediary.

### 2. Decisions — live/archive split

- **Rename** `knowledge/decisions.md` → `knowledge/decisions-live.md`.
- **Create** empty `knowledge/decisions-archive.md`.
- **No retroactive sweep** — existing 282 lines stay in `-live.md`. Attrition handles it as decisions get superseded in normal flow.
- **New entry format** (one decision = one line where possible):
  ```
  D-042 | 2026-06-17 | P14-4: surfaceGodPathCard removed; prep-tag system replaces it | spec:2026-06-17-god-path-prep-tags-design.md
  ```
- **Supersession workflow:** when a new decision reverses an old one, the new entry includes `SUPERSEDES: D-NN`, and the old entry's line is moved (`git mv`-style cut/paste in the same commit) from `decisions-live.md` to `decisions-archive.md`, with a `SUPERSEDED BY: D-MM` suffix appended.
- Full rationale lives in the linked spec (in `Code/project-abyssial/docs/superpowers/specs/`), not in the decision ledger.

### 3. Sessions — rolling window + handoff

- **New file** `knowledge/sessions/handoff.md`. Overwritten at every shutdown. Schema:
  ```
  UNCOMMITTED: <files or "none">
  LAST_COMMIT: <sha> <subject>
  NEXT_UP: <one line>
  BLOCKED: <one line or "none">
  OPEN_COMMITMENTS:
  - <one line>
  ACTIVE_SPEC: <path or "none">
  ACTIVE_PLAN: <path or "none">
  TESTS: <pass count> / <total>, typecheck <pass|fail>
  ```
- Target: < 30 lines, < 400 tokens.
- **Rolling window:** at shutdown, any `session-NN.md` more than 3 sessions old gets moved to `knowledge/sessions/archive/`. Current sweep moves sessions 52–83 to archive; 84, 85, 86 stay hot.
- **`session-NN.md` continues to be written at shutdown** — it's the durable per-session narrative — but is not part of mandatory startup reads.

### 4. Architecture — auto-derived inventory

- **New file** `knowledge/architecture-inventory.md`, regenerated by `scripts/gen-knowledge-arch.ts`.
- Format:
  ```
  src/state/gameStore.ts  | 1247 LOC | exports: useGameStore, resolveOption, ...
  src/engine/godPath.ts   |  312 LOC | exports: checkCondition, advanceGodPath, ...
  ```
- Walks `src/**/*.{ts,tsx,css}`, computes LOC and top-level exports (named exports + default), one line per file.
- Lets Claude locate a symbol's home file by grep without reading directory listings.
- **`architecture.md` keeps** its hand-authored narrative (types, conventions, module layout philosophy). The file-inventory section is removed and replaced by a single pointer line to `architecture-inventory.md`.

### 5. README — routing table, not tour

- Rewrite `knowledge/README.md` as a flat "if task is X, read file Y" lookup table for Claude. 40 lines max. No prose preamble.

### 6. Tooling — pre-commit hook

- Install `husky` (standard for Vite/TS).
- Pre-commit hook runs `gen-knowledge-cards.ts` and `gen-knowledge-arch.ts` and stages the regenerated files. Always fresh, zero manual step.
- **Failure mode:** if either script throws, hook prints a warning and `exit 0` (does NOT block the commit). The derived files might be stale until the next successful commit, but commits are never blocked by knowledge tooling.

### 7. CLAUDE.md routine rewrite

**New startup routine (mandatory reads, in order):**
1. `knowledge/README.md` — routing table
2. `knowledge/sessions/handoff.md` — current state
3. `knowledge/backlog.md` — priorities

Floor cost: ~1000 tokens. Everything else is grep-on-demand:
- Card work → grep `cards/INDEX.md`, then read the `.ts` directly
- Symbol lookup → grep `architecture-inventory.md`
- Decision check → grep `decisions-live.md`
- Bug recurrence → grep `bugs.md`
- Prior-session detail → read `session-NN.md` only when handoff explicitly references it

**New shutdown routine (in order):**
1. Append a new `knowledge/sessions/session-NN.md` (full narrative)
2. **Overwrite** `knowledge/sessions/handoff.md` with new state (use the schema in section 3)
3. Move any session > 3 files old to `sessions/archive/`
4. Append new decisions to `decisions-live.md`; if any decision supersedes an older one, move the old entry's lines to `decisions-archive.md` with `SUPERSEDED BY: D-NN`
5. Update `backlog.md`, `bugs.md` as needed
6. Pre-commit hook auto-regenerates `cards/INDEX.md` and `architecture-inventory.md`

**Removed from routines:**
- "Read the most recent session-NN.md" — replaced by handoff.md
- "Update knowledge/cards/{card-id}.md" — those files no longer exist
- Hand-edit of derived files — hook owns them

**New self-check item** in CLAUDE.md's behavioral self-check block:
> Did I just finish a session? If so, **overwrite** handoff.md before telling user to `/clear`.

## Migration steps (one-time)

1. Write `scripts/gen-knowledge-cards.ts` + `scripts/gen-knowledge-arch.ts`; commit their initial output.
2. Delete the 14 `knowledge/cards/*.md` hand-summary files.
3. Rename `decisions.md` → `decisions-live.md`; create empty `decisions-archive.md`.
4. Move sessions 52–83 to `knowledge/sessions/archive/`; keep 84, 85, 86 in hot folder.
5. Hand-author the first `handoff.md` (current state snapshot — includes uncommitted P14-4 content-pass status, etc.).
6. Replace `architecture.md`'s file-inventory section with a pointer to `architecture-inventory.md`; keep the narrative.
7. Rewrite `knowledge/README.md` as a routing table.
8. Install husky, configure pre-commit hook with non-blocking failure mode.
9. Update `CLAUDE.md`: new startup/shutdown routines; remove obsolete instructions; add handoff.md self-check line.

## Out of scope

- `knowledge/agents/*.md` — persistent agent memory, correctly hand-authored.
- `knowledge/bugs.md`, `knowledge/backlog.md` — hand-curated, untouched.
- `knowledge/investigations/`, `knowledge/infrastructure.md` — untouched.
- `knowledge/backlog-archive.md` — untouched.
- Retroactive splitting of the 282 lines of historical decisions — attrition handles it.
- Any change to `Code/project-abyssial/docs/superpowers/` specs/plans.
- Cold archives (`claude-history.md`, `claude-history-archive.md`) — untouched.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Pre-commit hook breakage blocks commits | Hook script catches exceptions, prints warning, `exit 0`. Knowledge tooling never blocks commits. |
| `handoff.md` only works if updated every shutdown; easy to forget | New line in CLAUDE.md behavioral self-check; shutdown routine puts handoff overwrite at step 2 (not last). |
| Deleting 14 card .md files is destructive | Git history preserves them. README and CLAUDE.md updated in same commit to point at `INDEX.md` + `.ts` files, so no lingering references invite "ghost reads." |
| Derived files drift if hook fails silently | `architecture-inventory.md` and `cards/INDEX.md` include a generation-timestamp header line. Anomalous staleness (timestamp older than recent commits touching source) is greppable. |
| Auto-extracting "top-level exports" via regex is fragile | Use the TypeScript compiler API (`ts.createSourceFile` + walk top-level statements) rather than regex. Slower but correct. |
| `flavour_hash` churns the INDEX on every minor copy edit | Acceptable — INDEX is generated, not hand-maintained. Churn is invisible cost. |
| Index format becomes useful for humans and they want it pretty | Resist. The whole design pivot is "Claude-first." Document this in the spec and in the generated file's header. |

---

## Success criteria

- Mandatory startup reads total < 1500 tokens (vs. current uncapped, often > 5000 due to long session-NN.md).
- Zero hand-summary card files; all card lookups go via `INDEX.md` grep → `.ts` read.
- `decisions-live.md` contains only un-superseded decisions; querying "what is current truth on X" is a single grep.
- Pre-commit hook keeps derived files fresh without manual intervention.
- After two sessions of normal operation, no instance of Claude reading a stale hand-summary or a superseded decision as authoritative.
